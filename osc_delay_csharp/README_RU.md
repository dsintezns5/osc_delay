# OSC Delay — C# (один .exe, без Python)

## Что это

Порт `osc_delay.py` на C# (.NET Framework 4 + WinForms). Итог — `OSC_Delay.exe` 36 КБ.
**Не нужно ничего устанавливать:** .NET Framework 4 входит в каждую Windows 10/11, WinForms тоже.
Логика прокси идентична Python-версии: задержка UDP-пакетов OSC, генерационный сброс
очереди при смене задержки, фильтр `/…` и `#bundle\0`, лимиты 50000 пакетов / 64 МиБ.
Настройки — тот же файл `%LOCALAPPDATA%\OSC_Delay_RU\settings.json`. Окно — то же самое
(русское, тёмное), счётчики и поведение 1:1 с Python-версией.

## Запуск (на любом Windows, только готовый exe)

1. Скопируйте папку на нужный компьютер.
2. Дважды нажмите `OSC_Delay.exe`.

Никакой установки Python, компилятора или библиотек не требуется. Windows один раз спросит
разрешение сетевого доступа: приложение принимает только локально, 127.0.0.1.

## Сборка из исходников (нужен только штатный компилятор)

`build.bat` собирает `OSC_Delay.exe` и тесты, затем сам прогоняет тесты (13 строк `PASS:`).
Нужен только компилятор `csc.exe` из .NET Framework 4. Он **уже есть в каждой Windows 10/11**:
обычно `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`.

`build.bat` находит компилятор сам, по порядку:
1. переменная окружения `CSC_PATH` (полный путь к `csc.exe`) — ручной override, самый приоритетный;
2. файл `csc_path.txt` рядом с `build.bat` (одна строка = полный путь) — ручной override;
3. реестр `HKLM\SOFTWARE\Microsoft\.NETFramework` → `InstallRoot` (работает, если .NET на другом диске);
4. стандартные папки `%SystemRoot%\Microsoft.NET\Framework64` и `\Framework`, версия `v4.0.30319`;
5. поиск самых новых папок `v*` в этих папках.

Если компилятор в необычном месте и автопоиск его не нашёл: создайте `csc_path.txt` рядом
с `build.bat`, одной строкой полный путь (например
`C:\Windows\Microsoft.NET\Framework\v4.0.30319\csc.exe`), и запустите `build.bat`.
`build.bat` печатает `Using compiler: <путь>` — видно, какой компилятор выбран.

## Подключение

Схема та же:

```text
VRCFaceTracking → 127.0.0.1:9015 → OSC_Delay.exe → 127.0.0.1:9000 → VRChat
```

Полное описание, диагностика, ограничения и возврат к прямой схеме — в витринном `README_RU.md`
ветки `main` (текст относится и к этой версии). Окно, счётчики, порты 9015/9000 — те же.

## Тест

`test_proxy.exe` проверяет: сохранность payload, задержку, сброс старой очереди при смене
задержки, сохранность OSC bundle, порядок пакетов, освобождение входного порта при остановке,
нейтральные значения при остановке. В песочнице разработки UDP loopback 127.0.0.1 блокируется,
поэтому тест использует реальный NIC-адрес машины; на домашнем ПК работает и на 127.0.0.1.
Прогон 2026-10-31: все 7 проверок PASS.
